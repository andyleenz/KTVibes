# Default theme redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the canvas spikes into the Default theme: a restyled TV player, a phone remote that handles a big library, two- and three-column layouts on wider screens, and word-by-word live lyrics on the remote. Classic stays behind a flag.

**Architecture:**
- The work restyles the existing Default markup, CSS and JS in place: `static/tv.*`, `static/remote.*` and `static/style.css`.
- The server gains two things: a Classic flag (an env var, read in `/api/config` and in `State`) and `GET /api/current/lyrics`.
- No new pages or frameworks.

**Tech Stack:** FastAPI and Python 3 (unittest via `uv run python -m pytest`), plain ES modules and CSS.

**Spec:** `docs/superpowers/specs/2026-11-21-default-redesign-design.md`

**Visual targets:**
- The spikes are generated by `dist/spike/build.py` (TV), `dist/spike/build_remote.py` (phone) and `dist/spike/build_remote_wide.py` (wide).
- They render to `dist/spike/screens/*.html`, served at http://localhost:8811/ (`python3 -m http.server 8811` in `dist/spike/screens`).
- Match their layout, type and colour. Lift CSS values from the build scripts.

## Global Constraints

- **Copy is matter of fact.** Use these exact strings:
  - Status: "Preparing 42%", "Error preparing", "No matches", "Search unavailable · offline", "Added · #N".
  - Banners: "Reconnecting to TV…" (button "Retry"), "TV sound off · click the TV to start".
- **Names:**
  - The prepared-song list is "Ready to sing".
  - The queue is "Queue" on both the TV and the remote, never "Up next".
  - YouTube results are "More songs", never "From YouTube".
- **Search placeholder:** "Song or artist", English only.
- **No ALL CAPS labels or eyebrows** in Default. Use sentence case at 15px or more on the TV.
- **TV overlays stay subtle.** No remote controls duplicated on the TV beyond the existing floating bar.
- **Classic stays selectable in Settings.** It is not restyled, but nothing in it may look broken.
- **Before each commit, run `uv run python -m pytest -q`.** Every test must pass.
- **Commits end with:** `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **No lyrics for the current song** (`lyrics` null or empty). The remote lyrics view shows "No lyrics" and doesn't crash. This belongs to Task 7.
2. **A very large library** (1,000+ prepared songs). The library screen renders without jank: it builds rows once, and filtering only toggles them. This belongs to Task 5.
3. **Long or mixed-script titles.** They clamp to two lines on remote rows and to three on the TV card, and never push buttons off-screen. This belongs to Tasks 3–5.
4. **The TV disconnects or reconnects mid-song.** The remote's banner shows and clears, and the lyrics view keeps its place by re-syncing from `position`. This belongs to Tasks 4 and 7.
5. **A saved `theme: classic` while the flag is off.** It loads as Default with `room_ends` cleared. This belongs to Task 1.

### Task 7: Live lyrics view on the remote

**Files:**
- Create: `static/remote-lyrics.js`, a module exporting `openLyrics()`.
- Modify: `static/remote.html` (the `#lyrics-view` layer), `static/remote.css`, `static/remote.js` (wiring the `#open-lyrics` button and state updates)

**Interfaces:**
- Consumes: `GET /api/current/lyrics` (Task 2), `state.position`, `state.playing`, `state.current.key`, `state.lyrics_rev` and `state.offset` from the existing socket state.
- Produces:
  - `openLyrics()` shows the layer and `closeLyrics()` hides it.
  - `lyricsState(state)` is called from `remote.js` on every state update.

**Behaviour (target `r10-lyrics`):**
- The background is the song art, blurred. A header shows art, title and artist, plus a close button (⌄).
- Lines come from the `units` of each lyric line. Each unit is a span.
- The playhead is `position + (now - receivedAt) * speed`, counted only while playing, plus `offset`.
- **Highlighting:**
  - A unit with `end <= playhead` is `.sung` (solid white with a soft glow).
  - The unit spanning the playhead is `.cur`, with `--f` set to the fraction sung (a left-to-right fill).
  - Later units are dimmed (`#ffffff59`).
  - Past lines fade to `#ffffff40`, and the next line is `#ffffff73`.
- The current line scrolls into place about 30% from the top, using `transform` with the same easing as the spike. Scrolling by hand pauses auto-scroll for 4s.
- The footer has the progress bar, then settings, play/pause and skip.
- A song with no lyrics shows "No lyrics". The view refetches when `key` or `lyrics_rev` changes.
- `requestAnimationFrame` runs only while the view is open.

- [ ] **Step 1:** the module, markup and CSS.
- [ ] **Step 2: Verify** against a real song on the running server. The fill should stay in step with the TV within about 0.2s. Check that pause stops it, and that seeking and skipping re-sync.
- [ ] **Step 3:** commit: "Remote: live lyrics, word by word".
